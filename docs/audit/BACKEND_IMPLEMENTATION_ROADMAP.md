# خارطة تنفيذ التكامل

## الهدف الأدنى للعرض

الحد الأدنى المتكامل هو: حساب طالب وسائق موثقان، موافقة مدير على السائق، إنشاء مسار من السائق، بحث الطالب في المسارات الحية، طلب مقعد، قرار سائق ذري، تحديث المقاعد وحالة الطالب، ورؤية تشغيلية للمدير. بلاغ أساسي من الطالب أو السائق مع قرار إداري ورد قابل للتتبع ضمن الحد الأدنى المطلوب في موجز المنتج. لا تكفي عروض المتصفح المنفصلة لإثبات هذا المسار.

| الميزة | النطاق |
| --- | --- |
| تسجيل السائق وموافقته، هوية الطالب، المسار والبحث، الطلب والقرار والمقاعد، تتبع الحالة، رؤية المدير، صلاحيات الموارد، بلاغ أساسي | مطلوب للحد الأدنى |
| الانتظار الموحد وتحليل الفرص، إشعارات داخلية بسيطة، تقارير إدارة أدق | موصى به إذا سمح الوقت، مع الحفاظ على معنى الطلب. |
| تتبع المركبة المباشر، الخرائط الدقيقة، التقييمات، رسائل تلقائية، تعدد جداول الرحلات، إعدادات تشغيل واسعة | بعد الحد الأدنى |

## أول مهمة تنفيذية آمنة

اتفقوا على عقد طلب المقعد، حالات الطلب والتسجيل، مصدر المعرّفات المعيارية، معنى السعة، ونطاق بلاغ الدعم في وثيقة تصميم قصيرة. بالتوازي تحقّقوا من اسم فرع `Neon` المتصل وأعدّوا فرع تطوير ونسخة استعادة. لا يُنشأ ترحيل أو يُكتب إلى قاعدة قبل هذين الشرطين. بعد الموافقة، ابدأوا بخط أساس ترحيلات للمخطط الحالي على فرع التطوير ثم جدول الطلب وقيوده.

## بوابات العرض النهائي

1. حساب طالب حي ومصادقة محمية، وتسجيل سائق وموافقة مدير على بيئة تجريبية مشتركة.
2. مسار ينشئه سائق ويظهر للطالب والإدارة بنفس المعرّف والبيانات.
3. طلب طالب يراه سائقه، ويُقبل أو يُرفض مرة واحدة مع تحديث الطالب والمقاعد والإدارة.
4. فحص تزامن يمنع المقعد الزائد والتسجيل المكرر، مع منع سائق غير مالك وطالب غير مالك للبيانات.
5. بلاغ حي يراه صاحبه والمدير، مع رد عام محفوظ وخصوصية الملاحظات.
6. خطة إعادة ضبط بيانات العرض ونسخة استعادة معروفة؛ لا يعتمد العرض على صفوف إنتاج حساسة.

## ما لم يُنفذ الآن

هذه خارطة عمل فقط. لم تُنشأ ترحيلات أو فروع `Neon`، ولم تتغير واجهات أو خادم أو سجلات، ولم يُنشر التطبيق.
