# تدقيق جاهزية دارب جو للتكامل الكامل

## نطاق الدليل

أُجري التدقيق على فرع العمل المحلي كما هو في 9 تشرين الأول 2026. شمل فحص الشيفرة، مخطط `Neon PostgreSQL` بقراءة حصرية، واختبار الخادم الموجود على قاعدة `SQLite` داخل الذاكرة. لم تُفحص سجلات المستخدمين، ولم تُختبر الكتابة إلى `Neon`. تعديلات واجهة السائق الموجودة قبل هذا التدقيق بقيت كما هي.

التصنيفات: `READY` تعني وجود عقد متطابق واختبار فعلي؛ `PARTIALLY READY` تعني وجود جزء عامل مع نقص محدد؛ `BLOCKED` تعني غياب اعتماد أساسي؛ `DEMO ONLY` تعني حالة متصفح معزولة؛ `NOT IMPLEMENTED` تعني غياب الواجهة أو العملية.

## خريطة المعمارية والتقنيات

| الطبقة | الموجود فعليًا | الملاحظة |
| --- | --- | --- |
| الواجهة العامة والطالب والسائق | ملفات `HTML` و`CSS` و`JavaScript` مباشرة | لا يوجد إطار واجهة أو بناء حزم. |
| الإدارة | ملفات `HTML` و`CSS` و`JavaScript`، عميل `admin/JS-file/apiClient.js` | تعتمد على طلبات موثقة إلى `FastAPI`. |
| الخادم | `FastAPI` مع موجهات تحت `src/admin/routers` | يوجد فصل محدود للخدمات؛ منطق الأعمال متركز في الموجهات. |
| البيانات | `SQLModel` و`SQLAlchemy` و`psycopg` | المحرك يستخدم `DATABASE_URL` و`pool_pre_ping`. |
| قاعدة البيانات | `Neon PostgreSQL` | فُحصت فهارس المخطط، لا محتوى الجداول. |
| المصادقة | رموز `JWT` للسائق والمدير؛ تخزين متصفح تجريبي للطالب | دخول الطالب من الخادم يعيد ملفًا بلا رمز جلسة. |
| الاختبارات | اختبار `pytest` واحد للخادم، وأدوات فحص واجهة | اختبار الخادم يستخدم `SQLite` معزولًا. |
| الترحيلات | لا توجد ملفات ترحيل أو جدول `alembic_version` | وجود الجداول لا يثبت وجود تاريخ ترحيلات. |

المسار الفعلي للإدارة والسائق في العمليات المدعومة: المتصفح ← `FastAPI` ← `SQLModel` ← `Neon`. مسار بحث الطالب وطلب المقعد والانتظار يبقى ضمن بيانات تجريبية في المتصفح؛ لا يصل إلى الجداول المشتركة. راجع العقود في `API_CONTRACT_INVENTORY.md` والمخطط في `NEON_DATABASE_GAP_ANALYSIS.md`.

## جاهزية واجهة الطالب

| الميزة | الواجهة والمصدر | التصنيف | الاستمرارية والحالات والنقص |
| --- | --- | --- | --- |
| التسجيل | نموذج فعلي؛ `DarbAccounts.create` | `DEMO ONLY` | يكتب إلى `localStorage`؛ لا سجل طالب في `Neon`. توجد حالة نجاح وخطأ، لكن لا تحقق خادمي. |
| الدخول | حساب المتصفح أولًا، ثم `POST /auth/student-login` | `PARTIALLY READY` | الاستجابة الخادمية اسم وبريد ودور فقط، بلا رمز؛ الصفحات تعتمد على `sessionStorage.loggedInUser`. |
| لوحة البداية | بيانات `student/dashboard-data.js` مع معلومات الحساب | `DEMO ONLY` | حالات معاينة متعددة، ولا مؤشرات مشتركة مع السائق أو الإدارة. |
| البحث عن مسار | سجلات تجريبية محلية | `DEMO ONLY` | فرز وتفاصيل وحالات عدم تطابق؛ لا استعلام مسارات حقيقي. |
| تفاصيل المسار | نافذة من السجل التجريبي | `DEMO ONLY` | السعر والوقت والمقاعد والتقييم التجريبي لا تقابل حقول المسار الحالية. |
| طلب الانضمام وتتبع الطلب | حالة في `sessionStorage` | `DEMO ONLY` | قبول وتأكيد ورفض تجريبي؛ لا سجل طلب أو قرار خادمي. |
| قائمة الانتظار | حالة متصفح فقط | `DEMO ONLY` | لا تكتب إلى `routedemand` ولا تدخل تحليلات الإدارة. |
| الرحلة القادمة | الطلب المؤكد التجريبي | `DEMO ONLY` | لا جدول رحلة أو تسجيل مؤكد خادمي. |
| البلاغات والدعم | `student/reports-service.js` | `DEMO ONLY` | قائمة وإنشاء وحالات واجهة؛ لا تصل إلى الإدارة. |
| الإشعارات | بيانات تجريبية في لوحة الطالب | `DEMO ONLY` | لا جدول ولا واجهة خادم. |
| الملف الشخصي | قائمة حساب مختصرة | `PARTIALLY READY` | لا ملف طالب موثق يربط منطقة وجامعة ووقت الوصول بمعرّفات القاعدة. |

| البلاغات والدعم | نموذج وسجل تجريبيان | `DEMO ONLY` | لا واجهات مالك للبلاغات. |

| موافقات السائقين | قراءة الطلبات وتغيير الحالة | `PARTIALLY READY` | الحفظ فعلي؛ الرسالة عبر `WhatsApp` يرسلها المدير يدويًا. لا رفع مستندات فعلي. |

| المسارات | قراءة وإنشاء إداري وتغيير حالة | `PARTIALLY READY` | لا وقت/سعر/توقفات، ولا إنشاء أو تعديل من السائق. |

| البلاغات والشكاوى | قراءة إدارية وتغيير حالة | `PARTIALLY READY` | لا إنشاء من الطالب/السائق، ولا حفظ ملاحظات القرار أو رد عام. |
| الجامعات والمناطق | قراءة من القاعدة | `PARTIALLY READY` | الواجهة تعرض السجلات؛ نماذج الإضافة غير موصولة. يوجد موجه إداري بديل للإنشاء. |
| إنشاء مدير | `POST /admin/admins` | `PARTIALLY READY` | عملية خادمية واختبار معزول؛ مراجعة سياسة منح الصلاحيات مطلوبة. |
| الإعدادات | ملف المدير وتغيير كلمة المرور | `PARTIALLY READY` | مفاتيح التشغيل معطلة ولا تخزين لها. |

## العوائق الأهم

1. لا يوجد عقد موحد لمصادقة الطالب، وطلبات الطالب الحالية ليست سجلات قاعدة بيانات.
2. لا يوجد نموذج أو واجهة لطلب انضمام يمر من الطالب إلى السائق ثم إلى تسجيل مؤكد.
3. نموذج المسار لا يحمل الوقت والسعر والتوقفات اللازمة للعرض الحالي؛ واجهات الإدارة لا يمكن استعمالها بصلاحية السائق.
4. مخطط القاعدة لا يفرض حدود المقاعد أو منع تسجيل الطالب مرتين، ولا توجد ترحيلات قابلة للتكرار.
5. البلاغات لا تُنشأ من أصحابها، ونموذجها الحالي يكرر الوصف في عنوان البلاغ.
6. فرع `Neon` المرتبط بالاتصال المحلي لم يُثبت اسمه؛ الوثائق تذكر فرع إنتاج. يجب تعيين فرع تطوير قبل أي كتابة لاحقة.

## الاختبارات وحدود الاستنتاج

- فحص مخطط `Neon` نجح داخل جلسة قراءة حصرية. ثبتت تسعة جداول ووجود أعمدة النماذج الثمانية؛ لم تُقرأ بيانات الصفوف.
- اختبار `tests/test_admin_api.py` نجح: اختبار واحد على `SQLite` داخل الذاكرة، مع تحذير تقادم من مكتبة الاختبار.
- فحص واجهة السائق من المهمة السابقة اختبر ثماني صفحات في خمسة عروض شاشة باستخدام استجابة ملف سائق محاكية؛ لا يثبت اتصالًا إنتاجيًا.
- لم تُنفذ اختبارات واجهة شاملة للطالب والإدارة في هذا التدقيق، ولا اختبارات تزامن أو صلاحيات كائنات أو كتابة حية.
