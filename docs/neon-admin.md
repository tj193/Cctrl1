# ربط لوحة الإدارة مع Neon

## كيف يعمل الربط

`Neon` يستضيف قاعدة `PostgreSQL`. المشروع الحالي اسمه `DarbGo`، وفيه فرع قاعدة بيانات اسمه `production` وقاعدة اسمها `neondb`. فرع قاعدة البيانات مستقل عن فروع `Git`؛ تشابه الأسماء لا يعني أن نشر الكود أو دمجه يغيّر القاعدة تلقائيًا.

مسار الطلب في هذا المشروع:

```text
front-end/login.html -> FastAPI /auth/login -> SQLModel -> PostgreSQL on Neon
front-end/index.html -> FastAPI /admin/... -> SQLModel -> PostgreSQL on Neon
```

المتصفح لا يحتفظ بكلمة مرور قاعدة البيانات. خادم `FastAPI` وحده يقرأ `DATABASE_URL` من بيئته. بعد تسجيل الدخول، يعيد الخادم رمز `JWT`؛ وتستخدمه صفحات الإدارة لطلب البيانات. الخادم يفحص الرمز وحالة حساب المدير عند كل طلب.

صفحات تسجيل الطالب والسائق في جذر المشروع ما زالت نموذجًا محليًا يستخدم تخزين المتصفح؛ لا تُنشئ سجلات في `Neon`.

## إعداد الخادم محليًا

1. انسخ `.env.example` إلى `.env` داخل المشروع. ملف `.env` مستثنى من `Git`.
2. من صفحة المشروع في `Neon` اختر فرع قاعدة البيانات المناسب، ثم انسخ سلسلة الاتصال من `Connect`. استخدم فرع تطوير منفصلًا للتجارب، وليس `production`.
3. ضع السلسلة في `DATABASE_URL`. مع `SQLModel` و`psycopg` تبدأ السلسلة بـ `postgresql+psycopg://`. أبقِ إعداد `sslmode=require` الذي يقدمه `Neon`.
4. أنشئ قيمة عشوائية جديدة لـ `JWT_SECRET` طولها 32 حرفًا على الأقل، وخزّنها في `.env` فقط.
5. ثبّت التبعيات وشغّل الخادم:

```powershell
uv sync --dev
uv run uvicorn src.admin.main:app --env-file .env --host 127.0.0.1 --port 8000
```

6. من نافذة ثانية شغّل الموقع الثابت:

```powershell
uv run python -m http.server 5500 --bind 127.0.0.1
```

افتح `http://127.0.0.1:5500/front-end/login.html`. للتحقق من تشغيل الخادم افتح `http://127.0.0.1:8000/health`. لا يستدعي بدء الخادم إنشاء جداول أو تعديل بنية القاعدة.

إذا اختلف منفذ أو عنوان الموقع الثابت، أضفه إلى `ADMIN_CORS_ORIGINS` في `.env`، مع فصل العناوين بفاصلة. في النشر الحقيقي، وجّه طلبات `/auth` و`/admin` إلى خادم `FastAPI` على نفس نطاق الموقع عبر وكيل عكسي؛ ستستخدم الواجهة نفس الأصل تلقائيًا.

## الأمان والعمليات

كانت بيانات اتصال قاعدة البيانات ومفتاح توقيع الجلسات داخل مستودع `Git`. يجب تدوير كلمة مرور دور قاعدة البيانات في `Neon` وتغيير `JWT_SECRET` ثم تحديث القيم في بيئة الخادم. إزالة النص من النسخة الحالية لا تمحوه من سجل `Git`، لذلك تدوير الاعتمادات ضروري.

حساب المدير الظاهر في `Neon` منفصل عن عضوية مشروع `Neon`. صلاحية `Editor` تسمح بإدارة المشروع؛ ولا تُسجّل الدخول إلى لوحة الموقع بدلًا من حساب `user` الموجود في `neondb`.

استخدم فرع قاعدة بيانات للتطوير والاختبار. لا تشغّل اختبارات تنشئ سجلات على فرع `production`. اختبارات المشروع الحالية تعمل على `SQLite` معزول.

بعض الحقول في واجهة الإدارة، مثل هاتف الطالب وتقييم السائق والمفاتيح التشغيلية، ليس لها حقول مقابلة في نموذج قاعدة البيانات الحالي. تعرض الواجهة القيم غير المتاحة بوضوح، وتبقى المفاتيح التشغيلية معطلة حتى تُضاف لها بنية تخزين وسياسة تطبيق. رفع مستندات السائق في النموذج العام تجريبي ولا يرسل الملفات إلى `Neon`.
